## 根因

1. 一个镜头失败会触发大批次重新生成和整包审核。
2. 每次 Codex exec 重复探索代码、故事和证据，没有最小阶段上下文包。
3. ImageGen、视频 API、Suno 和 FFmpeg 受资源锁串行限制。
4. 网络 502、流中断和周额度限制造成长时间阻断。
5. 自动状态机停止后，后半程大量工作由主任务和临时 Agent 恢复，manifest 不能准确计时。
6. 哈希审核可靠但不够增量化。
7. 多层执行身份在用户界面中没有形成清晰的父子树。

## 保留的正确设计

- 不覆盖用户原片。
- 连续性状态合同。
- 视频供应商适配器。
- 哈希绑定独立审核。
- 逐目标文件完成判定。
- 发布尾帧、画框、黑块和文档渲染 QA。
- 内部状态与客户资料包隔离。

## 优化优先级

1. 建立真实运行账本和 Agent 树。
2. 镜头级冻结、重做和增量审核。
3. 阶段上下文包与内容寻址缓存。
4. 把确定性任务从模型上下文移到脚本。
5. 修复美元/CNY 与实际账单接入。
6. 受控比较 Luna X-high、Luna Max、Terra Medium。
7. 代理预览通过后每个正式版本只做一次高分辨率渲染。
