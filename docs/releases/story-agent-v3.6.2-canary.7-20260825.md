# Story Agent v3.6.2-canary.7（2026-08-25）

## 正式生图启动减重

- 将 `codex_story_images` 中混在一次 Luna 调用里的“全故事计划、视觉圣经、动作提示词、首批 15 张图片”拆成一次性控制规划与轻量正式出图批次。
- Runtime 在模型启动前立即写入只读 seed，固定镜头编号、原文、输入路径和哈希；Sol Medium 只负责一次逐镜导演判断，不调用 ImageGen。
- 合同投影、逐产物语义计划和视觉小样绑定由 Runtime 注入并校验，不再要求模型抄写固定字段。
- 图生视频 CSV、Markdown 和片段命名表由 Runtime 从已验证逐镜计划编译，不再让每个图片 worker 重复生成。
- Luna High 正式批次只读取当前批次的 shots、参考图、审核重做指令和精确输出路径；不再内联 48KB 合同投影，也不得重做全故事策划。
- 每张图片最多两次尝试；第一次失败必须更换参考/构图/拆解策略，第二次仍失败即停并保留证据。
- 一次性控制计划最多两次：第二次只定向修订控制字段；仍不通过则在任何 ImageGen 调用前停止。
- Dashboard 事件和状态记录明确区分“一次性控制规划（不调用 ImageGen）”与“正式图片批次”。

## 通用性

- 连续场景、角色知情状态和有限道具状态仍由通用字段表达；代码没有写死《七色花》、花瓣颜色、角色名或具体故事路径。
- 视觉小样门禁保留，但复杂道具不再被要求在一张多宫格中同时证明全部状态；正式逐镜只消费当前状态和已审核母状态参考。

## 验证

- 新增一次性控制计划只执行一次、不会提前调用 ImageGen 的回归测试。
- 更新合同消费者测试，验证五类投影保留在哈希绑定的正式计划中，而不重复塞入每批 Prompt。
- 针对性测试：`100` 项通过。
- 完整测试：`562` 项通过。
- `story_agent.py --help` 与 `story_agent.py run --help` 通过。
