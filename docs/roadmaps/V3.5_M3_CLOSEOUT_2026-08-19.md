## Mock、fail-closed 与 Protocol substitution

- Video、Keyer、Semantics、VisualDesign、Image 和 Music 有 allowlisted runtime profile；Product、Compositor、Release 和 Publish 通过 Protocol 直接注入离线 mock/fake，不增加第二套 runtime 路由。
- Image/Music 外部 mock 必须同时锁定 selected/required profile 与 selected/required execution mode；缺失或错配在真实 executor 之前 fail closed。
- 每个 Port 都有 deterministic mock 或 Protocol-only fake；consumer 只使用 Protocol 公开字段/方法，不读取 concrete adapter 私有属性。
- M3-Z Cross-Port smoke 在一个 Registry 中同时注册十个 mock，以 zero-call sentinel 拒绝任何 ImageGen、Grok、Suno、browser/external executor 调用。下游 Request 实际消费上游产物路径与 SHA-256。
- mock 不伪造正式 QA/review/receipt/currentness；可用于产品判定的 mock Result 明确 `production_eligible=false`。

## Quality Policy 与事实源边界

Quality Policy 留在 Runtime 和原 consumer：Story Contract review/lock、visual sample 机器 QA 与独立审核、story image P0、video motion/receipt、music input-hash QA、keying standing/wide-gesture evidence、Demo/Release geometry、六封面比例/尺寸/近似同图与独立视觉审核、PPT/文稿/标注/资料包 currentness 均未进入 Adapter。

Port Result 只是单次 invocation result，不替代 Story Production Contract、artifact semantic plan、visual sample lock、provider receipt、music QA report、keying lock、geometry/render manifest、cover lineage、product package manifest、hash-bound review 或 `project_manifest.json`。M3 未新增并行事实源。
