# 儿童故事分镜出图流程

## 适用场景

当工作台生成 `*_codex_image_request.md` 后，用本流程完成儿童故事的分镜图片阶段。

目标不是只生成好看的单张图，而是产出能继续进入图生视频流程的一组稳定素材：

- 分镜表
- 统一角色和场景设定
- 逐张 16:9 图片
- 一行一镜头的分镜文本
- 图生视频提示词文件

## 输入

优先读取任务书中的这些路径：

- 故事原文
- 分镜文本目标
- 最终图片目录
- 图生视频提示词目标
- 故事 slug

如果故事原文中已经有人工换行，优先把每个非空行视为候选镜头边界。可以为了节奏做轻微合并或拆分，但需要先在分镜表中说明。

## 标准流程

1. 读取任务书和故事原文。
2. 先输出分镜表给用户确认，确认前不要生成最终图片。
3. 分镜表至少包含：镜头编号、分镜文本、画面设计。
   - 同时保存机器可读的 `*_storyboard_plan.json`。每镜必须写 `scene`、`story_text`、`narrative_function`、`shot_size`、`focal_character`、`visible_characters`、`excluded_characters`、`continuity_group`、`appearance_ids` 和 `visual_description`。`story_text` 必须与权威分镜逐行一致。
   - 每个正在唱歌、说关键台词、做关键动作或发生明显情绪变化的角色，至少要有一个以它为画面焦点的独立镜头；不能因为主角也在场，就让所有表演者都长期和主角挤在同一个双人中景里。
   - 先列“叙事覆盖清单”：登场、独立表演/发言、受挫反应、关键劝告、结尾关系变化是否都有对应镜头。清单有缺口时先调整分镜，不得直接出图。
   - 如果分镜文本包含书名号标题，例如《故事名》，对应标题镜头必须把中文标题作为画面内文字直接生成在书卷、牌匾、封面或标题卡材质上，并在分镜表中明确写出“必须直接生成中文标题：故事名，不能后期加字”。
   - 如果结尾分镜包含“告诉我们”“道理是”“这个故事告诉我们”等总结句，必须把核心道理提炼成画面内卷轴/文本框文字，并在分镜表中明确写出“必须直接生成该中文文本，不能后期加字”。
   - 如果故事原文出现主持人或讲述者自称，例如“我是绵羊姐姐”，默认只当作旁白，不画出主持人/讲述者形象；只有任务书或用户明确要求出现时才作为角色入画。
   - 对连续发生在同一时空的情节段落，分镜表必须先标出“连续场景段”，并写清楚每个镜头的景别变化。例如同一段河岸对话可以安排为：大全景建立关系、中景给说话者、反打中景给回应者、双人中景承接、再拉回全景结束。不要让连续对话镜头全部都是同一种中景，也不要让背景环境在同一段里随机变化。
4. 用户确认后，先建立视觉圣经：
   - 主角年龄、脸型、发型、服装、关键道具
   - 主要场景的时代、空间、色彩和光线
   - 全片色温、主色调和禁用色调：例如“偏冷清亮、青绿水色、少量暖金点缀；避免脏黄、土黄、琥珀黄整片覆盖、过重褐色壁画感”。后续每张图的提示词都要继承这个色彩约束，不能一会儿偏黄一会儿偏白或偏冷。
   - 连续场景段的场景锚点：同一时空内必须锁定同一条河、同一棵树、同一条小路、同一组远山、同一块岸边空地、同一宫殿房间等可识别元素；只改变机位、景别、角色动作和表情。提示词中要反复写明“同一场景连续镜头，保持这些场景锚点不变”。
   - 为每个反复出现的角色建立稳定 `appearance_id`，逐字固定物种、性别/年龄感、脸部标志、服装颜色与款式、饰品。相邻镜头必须引用同一个 `appearance_id`；服装变化只有剧情明确要求时才允许，并要在分镜计划中写原因。
   - 生成后续镜头时，把风格锚点和同一角色最近一张已通过图片作为参考图继续生成；不得只复制一段文字提示后重新随机抽角色。
   - 整体风格：以任务书“画面风格”章节为准；如果任务书没有写，默认 16:9、明亮温暖、儿童友好、3D 卡通
   - 如果任务书选用“中国风2D绘本”或“水墨绘本”，视觉圣经必须明确线条、纸张肌理、国画/水彩设色、服装建筑时代感和禁用方向，不能继续套用 3D 卡通材质
5. 连续生成完整故事所需的全部图片，不要人为限制总张数，也不要把“每批 8 张以内”当作业务规则。如果工具、网络或工程中断，再检查目标目录里已经存在的 `{slug}_scene_XX.png`，从下一个缺失编号继续。
6. 不要把多宫格或联系表当作最终图片。最终必须是一张张独立的 16:9 图片。
7. 不要生成无关文字、水印、字幕、UI 或二维码。但如果分镜表明确要求画面中出现中文标题、匾额、书页、卷轴文字或结尾文字，必须把这些中文作为画面内容由图像模型直接生成出来。禁止用本地脚本、Pillow、HTML/SVG、截图、局部贴片、后期覆盖文字或任何非生图方式补字；那不算合格成片。生成后要核对指定文字是否自然融入书页/卷轴/牌匾等画面材质、是否出现、是否位置正确；如果缺字、错字、乱码、留白或像后期贴片，丢弃该图，用 Codex 图像生成重新生成该镜头。
8. 图片命名必须稳定：

```text
{slug}_scene_01.png
{slug}_scene_02.png
...
```

9. 把最终确认的一行一镜头文本写入任务书指定的 `*_storyboard_lines.txt`。这个文件每个非空行就是一个镜头，顺序必须和图片一致。
10. 同步生成图生视频提示词：
   - `*_flow_video_prompts.md`
   - `*_flow_video_prompts.csv`
   - `*_flow_clip_names.csv`
   - 图生视频已经有当前图片作为视觉约束，提示词只写动作表演、表情变化、关键道具运动、镜头运动和少量禁止项。
   - 不要把文生图视觉圣经、服装细节、画风长描述复制到图生视频提示词里；角色/服装/场景统一用一句“参考当前图片，保持角色、服装、场景不变”即可。
   - 每个镜头必须写一条“按本镜头故事情节创作”的图生视频提示词，不能批量套用同一段模板。例如“打瞌睡”要写眼皮合上、头往下低，“系绳”要写抬手系到发髻和房梁，“文字镜头”要写文字保持清晰稳定。
   - 这些 `*_flow_video_prompts.*` 文件是后续工作台准备图生视频时的优先来源；只有缺失时，工作台才会退回自动推断提示词。
11. 图生视频提示词需要人工确认后才能进入 API 生成：
   - 工作台“准备图生视频”后会打开审核页，用户需要逐镜头检查/修改提示词，并导出 `prompt_review_decisions.csv`。
   - “生成视频片段”前会读取该确认 CSV；如果缺失，或有镜头没有标记为通过，就不得调用图生视频 API。
   - 因此出图阶段写入的 `*_flow_video_prompts.*` 必须可供用户直接审阅：不要写空泛模板、不要复制文生图长提示词、不要让相邻镜头只有故事文本不同而动作提示相同。

## 质量要求

- 同一角色在所有图片中保持一致，不能换脸、换年龄、换衣服逻辑。
- 独立审核必须把角色逐一对照，而不是只看“整体风格像不像”：发型、脸部条纹/花纹、服装主色、领口/袖口、饰品任一无剧情依据的变化都算连续性错误。
- 同一故事世界中的道具、建筑、服装时代要一致。
- 同一时空的连续情节必须保持环境一致：场景锚点、光线方向、天气、时间、河流/道路/建筑/树木位置应连续。允许为叙事变化景别和机位，但不允许每张都换一套背景。出图前要把连续段当作一组来提示，出图后用联系表检查是否像同一场戏。
- 连续段必须有景别节奏：至少在大全景/全景、中景、近景或反打之间做合理变化，让观众看清人物关系、说话者表情和动作推进。不要让同一段连续台词全部生成同构图、同距离、同人物站位的画面。
- 全片色温和主色调必须统一。视觉圣经一旦确定“偏冷清亮”“明亮暖调”“水墨淡雅”等方向，后续提示词要持续约束天空、水面、阴影、背景和服装的色彩关系；发现某些图片明显脏黄、偏灰、偏暗、过暖或突然跳色时，要先重画这些图再交付。
- 画面风格以任务书为准；中国民间故事、神话故事、成语故事、历史故事可以使用中国风 2D 绘本/轻水墨绘本，不要强制复用通用 3D 卡通。
- 画面适合儿童观看，不出现恐怖、血腥、过暗或成人化表达。
- 不要生成无关文字、水印、字幕、UI 或二维码；分镜明确要求的中文文字必须由图像模型直接出现在画面里，并自然融入书页/卷轴/牌匾等材质。禁止本地后期加字、贴片或覆盖；发现这种情况必须重生该镜头。
- 对标题镜头和结尾道理镜头，不能只写“可出现文字”或“意象标题”；必须把要生成的中文逐字列入分镜表、视觉圣经和单镜头提示词，并在出图后逐字核对。
- 图生视频提示词也属于交付质量的一部分，必须逐镜头贴合分镜情节；发现提示词复制文生图视觉圣经、服装长描述，或只是在重复“轻轻推进、保持不变”等通用描述，要重写后再交付。
- 图生视频提示词确认是正式流程闸门，不是可选备注。交付前要提醒用户：回到工作台点“准备图生视频”后，先在审核页确认提示词并导出 `prompt_review_decisions.csv`，再点“生成视频片段”。
- 如果发现角色或道具漂移，先停下来修正提示词，再继续后续镜头。

## 交付检查

完成后确认：

- 最终图片目录存在，且图片数量与分镜文本行数一致。
- `*_storyboard_plan.json` 存在，逐镜覆盖叙事功能、焦点角色、景别、在场/不在场角色和 `appearance_id`。
- 图片都是 16:9 横图。
- `*_storyboard_lines.txt` 已保存。
- 图生视频提示词文件已保存。
- 最后告诉用户可以回到工作台点击下一步“准备图生视频”；准备完成后先审核/修改图生视频提示词并导出 `prompt_review_decisions.csv`，确认后再生成视频片段。
