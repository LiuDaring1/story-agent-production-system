# Codex 原生工作流

## 指挥官职责

Skill 与 Schema 都不是执行器：Skill 提供策略，validator 检查已实现的结构、语义约束和哈希引用。当前 Codex 任务读取检查结果后，亲自决定并调用下一个确定性模块或供应商；模块返回的实际文件、回执与 SHA-256 再由 Codex 和独立审核判断。完整责任链见 `docs/architecture/execution-chain.md`。

当前 Sol 任务只负责四件事：锁定输入、一次性导演规划、分派互不冲突的工作包、按哈希汇合产物。不要把制作细节重新写进一份大合同，也不要把完整项目上下文重复交给每个工人。

导演计划应一次给出：

- 原文与音频的语义镜头区间。
- R2V 资产清单与完整 `story-r2v-plan-v4`；v2/v3 只读兼容历史项目。
- Suno 情绪段边界。
- RVM、朗读标注、包装准备所需的输入路径。
- 需要等待的汇合点，不包含 A/B/C、封面或资料包模块已经固化的内部规则。

计划保存后，由新的独立上下文只审核一次完整计划。通过后先完成资产生成、资产 bundle 和资产独立审核，再生成逐镜故事板；故事板封存并整组独立审核通过前不得发起付费 R2V。

## 工作交接与审核依据

开工前生成并登记 `story-applicable-requirements/v1` 投影。投影不是第二份规则大全：它只绑定当前输入、实际规则源版本、本包适用范围、可执行参数检查和预期证据。用户明确要求覆盖默认时，`requirements` 项必须保留用户原要求、来源和范围，不得把默认值写回 `executable_checks`。外部视频任务入口会在任何 provider 请求前重新校验投影哈希和 model/ratio/resolution/seconds。

每个工作包在开始制作前读取适用的 Skill、工程配置/规则和已锁定的本故事计划。指挥官在已有任务交接或计划文件中给出以下最小信息，生产者与审核者共同使用；不要再建立一套调度器或复制全项目合同：

- 本包范围、当前输入路径及哈希。
- 适用的硬要求：原要求、来源文件及定位（或用户明确要求）、适用账号/镜头/产物。只摘录本包实际相关的规则；品牌默认、模型推断和用户要求不能混写。用户已明确覆盖默认值时，执行用户要求。
- 已有机器自检命令与需返回的证据。先执行自检，再交独立审核；发现确定性规则被违反，先修复本包，不把找规则的责任交给审核者。

审核交接复用同一份规则来源和版本，同时提供当前产物、机器结果与哈希，不附带生产者希望获得的结论。审核者先检查适用范围，再观看结果。每条退件记录「违反的既有要求及来源 → 实际证据帧/时点/页面 → 对交付的影响」。角色穿模、身份复制、因果或连续性错误可引用已锁定故事计划和现有视觉质量合同；无需用户提前枚举每种生成缺陷。

模型偏好、创意提醒或没有既有依据的额外阈值只能列为不阻断建议，不能降分到不通过，也不能驱动付费返工。例如：不能把 Logo 运动要求扩展成避让角色，不能把允许的短暂手掌出框改判为持续躯干裁切。这里的例子只解释既有规则边界，不新增审美规范。

指挥官在采取返工动作前核对退件来源、适用条件与证据。无效退件先纠正审核；作品仍须按原有要求得到有效通过结论。有效缺陷只影响对应产物及依赖，不扩大到已通过且哈希未变化的项目。这个交接约束不能替代程序门禁，也不能证明模型一定遵守了指令。

## 并行工作包

计划通过后优先并行：

1. R2V 视觉：先完成资产及审核，再按每个导演 `shot_id` 生成并封存故事板；同一故事板清单随后同时驱动正文 R2V 和静态 PPT。故事板与提示词锁定后默认批量并发提交全部正式镜头，禁止在没有真实尾帧复核收益的情况下逐条提交、逐条等待。
2. 音乐：Suno 提示、候选、下载、拼接与 `qa_music_report.json`。
3. 真人抠像：RVM 分析、候选帧、`keying_search.json` 和锁定前景母版。
4. 产品素材：朗读标注、发布文案、确定性包装准备。

每个工人只写自己的工作目录并返回产物路径、SHA-256、供应商任务号、时间、重试和错误类型。工人不得编辑其他分支、恢复旧 Job 或启动下游全片渲染。

发布美术登记为 `theme_assets_manifest` 时使用 `story-theme-assets-lightweight/v3`。清单至少包含当前故事的 `sources.environment`、`sources.story_frame_magenta`、`artifacts.main_background_16x9` 和 `artifacts.story_frame_png`：框源图必须绑定正式几何参考图 SHA-256，注明参考图只用于占位/开口/厚度，并证明造型按当前故事重新设计；源图内外均为纯 `#FF00FF`，透明框只允许对同一洋红栅格源图做色键/Alpha 后处理。清单还必须记录背景未预模糊、已控制高频碎细节且没有文字、Logo 或暗角。出现 SVG、棋盘格、白底、直接透明生图、细框或不连续四边时，`story_pipeline.py record/finalize` 必须阻断。

## 汇合顺序

- R2V 镜头并发下载后逐条做机器完整性检查，再生成低成本连续预览供导演整段观看。此预览只用于发现叙事、动作、景别/构图变化和明显交界异常，不是正式时间轴母版。导演校验工具可输出不阻断的创意提醒，用于请审核者复核长对白的画面承担和连续构图相似；提醒不得被转换为景别数量、构图重复率、气泡或闪回比例门禁。只有被标记的镜头才进入深复核或受控返工；首轮退件超过 30% 或同类缺陷至少 3 镜时先冻结付费重做并轻量校准退件集合。稳定版不启用真实尾帧继承或串行镜头链。整组视觉审核未通过前不得运行正式组装。
- 故事视觉母版与音乐通过机器 QA 后，生成含/无字幕背景视频；旁白、字幕和音乐不重复提取或规划。
- RVM 独立审核通过后，故事母版、前景母版和既有 A/B/C 配置生成两条发布视频及示范视频。
- 资产审核后运行 `shot_storyboard_pipeline.py`，为每个导演镜头生成一张完整句意的 ImageGen 插画并封存为唯一故事板清单。该文件同时是静态 PPT 主图和对应 R2V 镜头的最后一张语义参考；不得分别生成两套图，也不得把 AutoViz/R2V 帧或视频截图直接当作故事板。PPT 页 ID 只能来自导演计划 `TITLE + shot_id + 可选 MORAL`，不得从目录图片数或逐句文本数派生。
- 静态 PPT 双版按同一计划构建、内嵌配乐并写入自动翻页后，先通过机器校验，再把导演计划、故事板编译回执、PPT 计划和两份 PPTX 一并传给 `product_package.py`。打包器生成 `static_ppt_delivery_receipt.json`，最终账本必须登记它；因此上游计划正确但客户目录里的 PPT 被换页、改图或损坏，也不能通过 `finalize`。
- 封面等待代表性故事帧和真人帧后，继续调用既有封面流程。
- 下游失败先修复被证实有问题的分支；若根因位于上游则修复对应上游。输入哈希未变不能豁免已被有效 QA 判错的产物；修复后只使实际受影响的依赖失效，不无故重做全项目。

独立审核触发点只保留：导演计划一次、资产整组一次、故事板整组一次、RVM 锁定一次、R2V 连续预览与问题镜头合并一次，以及最终交付一次。产品/封面/发布机器 QA 仍各自运行；新项目的 `final-delivery-independent-review/v2` 合并客户媒体的音频、字幕、Logo、人物几何和证据检查，不再另造一份空壳客户媒体审核。只有局部哈希改变时，复审变化产物、相邻切点和显式依赖；全局叙事关系改变才扩大范围。

## 首个项目 canary

- 新建 `story_run.json`，不要恢复旧后台 Job。
- 先完成整故事导演计划与一次审核，再发起首个真实视觉任务。
- 首个视觉任务十分钟内没有任务回执即停止诊断。
- R2V、音乐、RVM 与产品素材并行；同一语义镜头不得拆成多次付费生成。
- 最终以完整双账号视频、两套资料包、含/无字幕两份静态故事 PPT、六张封面和当前 QA 哈希验收。
