# 故事朗读标注

把故事原文转成少而精、可实际表演的分段标注。不得用通用朗读套话代替文本判断。

## 工作流

1. 读取完整故事和资料包的脱敏口径。
2. 删除主持人身份句，如“大家好，我是____”；题目引入句可以保留。不得在客户资料中写入真实主持人姓名。
3. 按场景、角色或情绪转折分段。每段通常覆盖 2–4 句；对话跨行时保持引号和语义完整，不按输入行号机械切段。
4. 在 `marked_text` 中保留原文顺序和措辞，只增加标记：
   - `**词语**`：真正需要重读的内容词；
   - `/`：短停顿；
   - `//`：场景、角色或情绪转换的明显停顿。
5. 为每段写具体的 `emotion`，说明本段内部的情绪走向或角色切换。
6. 写 1–3 条 `notes`。每条必须引用本段的触发词或动作，说明怎么读，以及必要的目光、表情或上半身动作。
7. 输出纯 JSON 数组，不加 Markdown 代码围栏。

## 批注说话方式

- 把 `notes` 写成一位有经验的幼儿园故事老师在现场给朗读者的自然提醒：温和、口语化、短句、拿来就能演。
- 先说这一刻角色心里在想什么、看见什么，再落到声音或动作。例如：“说到‘谁愿意来唱歌’时，像真的在等小动物举手，眼睛慢慢扫过大家。”
- 优先使用“像……一样”“先……再……”和具体的小画面，少用“内容重点”“节奏落点”“情绪层次”“角色状态”等分析术语。
- 不向朗读者展示推理过程，不写评审腔、教案腔或参数腔。每条只解决一个最重要的表演问题。
- `emotion` 可以概括情绪走向；`notes` 必须像人对人说话，不能把 `emotion` 换个技术说法重复一遍。

不合格：`第二个节奏落点要突出判断感，完成内容重点的收束。`

合格：`说“这才是合格的评委”时放慢一点，像终于想明白了，认真地点一下头。`

## 标注边界

- 重音只标首次出现的重要角色或道具、关键动作、矛盾转折和故事道理关键词；不得整句连红，也不得每句都标。
- 不改变故事事实，不补写原文没有的台词，不删掉推动情节的句子。
- 引号必须成对；角色台词应与前后的提示语放在同一语义段内。
- 同一个动作只给一个清楚提示，避免同时安排手、脚和大幅走位。默认录制者站立口播，以目光、表情和上半身动作为主。
- 批注必须能从文本中找到依据。禁止“开头要说清楚”“语气生动一些”“注意节奏”等无触发词的通用套话。
- 道理段真诚、邀请思考，不用训话腔。
- `marked_text` 必须逐字覆盖经过审核的客户正文；除脱敏主持人身份外，不得把“她”换成“他”、增删形容词、改对白或用更顺口的句子替换原文。

## 输出契约

每个数组项只使用以下字段：

```json
{
  "title": "本段的情节或情绪标题",
  "marked_text": "带 **重音**、/、// 的原文",
  "emotion": "具体情绪基调和转折",
  "notes": [
    "引用本段触发词的具体朗读或表演提示。"
  ]
}
```

交付前逐项检查：所有正文句子逐字覆盖且仅覆盖一次；主持人身份已脱敏；没有空字段；没有泛化或技术腔批注；JSON 可解析。
