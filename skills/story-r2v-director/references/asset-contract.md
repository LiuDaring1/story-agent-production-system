# R2V 资产合同

## 两层角色资产

三视图在角色设计阶段有价值，但运行时直接上传三视图可能让视频模型把同一身份理解成多个角色。把角色资产分成两层：

1. `design_master`：三视图、表情表或设计稿，用于锁定造型、人工审核和派生运行时资产；标记 `runtime_eligible: false`。
2. `runtime_reference`：一张只显示一个角色的干净参考图；优先全身或四分之三视角、自然站姿、四肢清楚、背景简单；标记 `runtime_eligible: true`。

资产库可以为同一身份保存多个运行时角度，但单个视频请求只能选择其中一个。不要在同一请求中同时发送同一角色的正面、侧面和背面图。

## 群像不是统一一种处理

先按“观众是否必须认出并在后续镜头持续追踪”分级：

1. **身份关键群像**：每个成员都是故事角色，脸、服装或状态需要连续。每个成员各选一张单人物运行时图。五个身份关键角色可以使用五张角色图，再加一张空环境图；若关键道具等使总数超过 7，必须重新安排构图、减少同镜头可读身份或按真实剪辑理由拆镜。
2. **重复出现但不逐人追踪的群体**：使用一个 `population` 资产约束年龄层、服装、物种、时代和色彩。通常使用一名匿名代表或不含人物站位的服装/材质参考。只有当数量直接决定剧情因果、教学答案或后续状态变化时，才改用一张成员全部可数、遮挡极少、姿态互异的固定数量群体资产；原文偶然提到一个数量，但画面主要任务是表现追逐、恐惧、热闹或规模感时，数量属于软事实，不应牺牲动态表演去逐帧锁数。
3. **一次性匿名背景人群**：通常不需要逐人参考。用空环境、人数范围、密度、位置、行为和面部可读性指令让视频模型生成；只有群体造型容易偏离视觉体系时才增加一个 `population` 资产。

近景中能辨认面孔、需要说话、交付道具、触发剧情或下一镜继续出现的人，不能伪装成匿名群众以节省槽位。远景中只承担氛围、没有独立身份和后续连续性的人，也不要机械地一人上传一张图。

参考图数量合规不等于表演一定可靠。四个以上身份关键角色同时清晰露脸时，优先让群像镜头承担建立空间关系和一个简单共同动作，再在后续 R2V 镜头中切到较小角色组合。若五个人都要在同一个 10 秒镜头内分别说话、走位或操作不同道具，应依据视觉焦点拆镜，而不是继续堆导演指令。

## 资产类型

### Character

必需字段：

- `asset_id`
- `kind: character`
- `identity_id`
- `path` 与 `sha256`
- `runtime_eligible`
- `contains_characters`，只能包含该 `identity_id`
- `appearance_summary`
- `scale_class`

同一镜头引用资产的 `identity_id` 必须唯一。角色与其他角色的相对尺度由镜头计划约束，不通过上传多人合照表达。

角色运行时资产不得含导演计划和故事文本没有依据、却会被视频模型持续继承的抢眼配饰或束缚物，例如多余绳带、锁链、徽记、武器、首饰、发光纹样或异常伤痕。儿童向服装用于遮挡和造型的必要系带可以保留，但必须与服装结构一体、不会被误读为捆绑，也不能在腕、踝、颈或躯干形成无意义的重复缠绕。资产审核要把这类内容作为独立检查项；发现后优先修正资产，不能指望每个镜头的文字提示反复压制。

### Environment

环境资产必须是空场景：

- `kind: environment`
- `contains_characters: []`
- 无临时人物、动物或人物影子
- 锁定地点、时段、天气、光线方向、主要色彩与可识别锚点
- 同一连续场景组复用同一 `environment_asset_id`

环境资产描述空间本身，不描述本镜头的角色站位。角色站位属于导演提示词。

同一地点若在故事中发生可见状态变化，例如昼夜、季节、天气、损坏/修复、开灯/关灯或陈设改变，应保留共同地点身份并建立状态特定的空环境资产。各状态复用相同的建筑结构、地形、视角锚点和比例，只改变导演计划声明的环境状态；相邻镜头通过不同 `continuity_group` 的 `time_of_day`、`lighting`、`anchors` 和 `scene_change_basis` 记录变化依据。没有环境变化的故事不要制造多余状态。

### Population

群体造型资产使用：

- `kind: population`
- `population_id`
- `contains_characters: []`，不承诺任何身份关键角色
- `design_source_kind: population_archetype`
- `runtime_eligible: true`

同一镜头最多选择一个群体造型资产。显示固定人物站位、精确队形或故事构图的群像设计稿属于 `ensemble_design_master`，只能作为设计资料，不能直接投喂运行时。

若数量属于剧情关键硬事实（例如少一个就改变谜底、因果或后续操作），单个匿名代表容易被模型任意复制。此时运行时 `population` 资产必须直接包含恰好 N 个成员，并满足：

- 所有成员完整可见、易于逐一计数，遮挡尽量小；
- 姿态、尺度或朝向略有差异，避免被理解为镜像复制；
- 使用中性背景，不携带故事地点、剧情走位或身份关键角色；
- 提示词在开场、动作过程和收尾三处都锁定相同数量；
- 付费前机器/计划审核同时核验资产内数量与 `crowd_plan.exact_count`。

这类固定数量资产仍使用 `design_source_kind: population_archetype`，因为它是匿名群体的运行时造型母版，不是含剧情走位的分镜图。

若数量只是旁白中的软事实，审核记录实际可见数量即可，不因短暂遮挡或近似数量触发付费重做；更不能为了锁数量，把运动镜头替换成静态群体图。最终交付的运动完整性、表演和剪辑连续性优先。

### Prop

有限道具和会变化的道具必须有 `prop_id` 与 `state_id`。状态 ID 应表达稳定、可审核的事实，如 `complete`、`one_component_removed`、`broken` 或 `repaired`，通用代码不得写死任何故事内容。每次请求对同一个 `prop_id` 只能选择一个入口状态资产。

运行时道具图必须只呈现可携带的道具本体，使用透明或简单中性背景；不得保留原场景、土壤、家具、人物手部或强定向环境光，以免和镜头自己的空环境发生构图泄漏。`absent`、`none`、`removed` 等负向状态不创建道具图片，也不占参考图槽位；具体状态迁移规则见 [stateful-props.md](stateful-props.md)。

数量为一的剩余部件不要用正面对称构图。单瓣、单叶、单翼、单把手等容易被模型镜像成两个的状态，运行时图应采用三分之四视角，把唯一部件放在中心轴一侧，并让另一侧明显留空；提示词同时写明“总共恰好一个”和空侧位置。

每个运行时道具还必须记录 `physical_contract`，至少包含：

- `scale_basis`：它相对人物是单手、双手、身体、家具还是环境尺度；
- `support_mode`：由谁拿着、独立站立、落地、悬挂、附着或松散放置；
- `rigidity`：刚性、柔性、柔软、易碎或流体；
- `grip_or_contact`：手、绳结、桌面、地面或连接点应如何接触；
- `forbidden_inferences`：不得自动推断的形态，例如“不得改变载体或无依据放大”“柔性物不得变成硬质闭环”。

参考图必须为这份合同提供视觉证据。手持小道具应保留可辨识的手持尺度和抓握区域，但不把真人手、土壤或完整故事场景烧进资产；需要独立支撑的对象才展示底座或落地点。柔性绳、带、布等应在重力下自然下垂、弯折并略微不对称，避免正圆、完美水滴闭环或悬空定型。审核若只看见“形状像”，却不能判断尺度、支撑和刚柔，资产仍不合格。

## 多状态道具使用同源母版

同一个 `prop_id` 存在两个以上运行时状态时，不要分别从文字独立生成。采用一个轻量的“母版—派生”流程：

1. 先生成并审核一张最能代表对象身份的干净母版，锁定整体轮廓、材质、颜色、相对尺度和观察角度。
2. 列出每个 `state_id` 相对母版唯一允许改变的 `state_delta`，例如只减少一个部件、只改变完整性或只清空承载物。
3. 每个状态都以同一母版作为图像编辑输入逐张派生；失败时只重做该状态，不重新设计整个道具。
4. 把所有派生状态并排做一次家族审核，确认除声明的 `state_delta` 外没有换形、换材质、缩放或镜像。并排联系表仅作审核证据，运行时仍只上传当前入口状态的一张图。

每张派生资产记录相同的 `state_family_id`、`state_family_master_path` 和 `state_family_master_sha256`，并记录自己的 `state_delta`。同一家族必须保持 `scale_class`、`physical_contract.scale_basis` 和 `rigidity` 一致；支撑方式和接触点可以随剧情状态变化，不强行锁死。

只有一个运行时状态的普通道具无需建立状态家族。不要为了满足流程而制造无用状态图。

## 状态特定的角色姿态

普通身份参考优先自然站姿，但当“保持坐着、躺着、被搀扶、不能站起、持续抱住某物”等姿态本身是当前镜头不可改变的故事状态时，站姿参考会强烈诱导错误动作。此时应为同一 `identity_id` 派生一张状态特定的单人物运行时图：

- 身份、脸、发型和服装与设计母版一致；
- 只改变当前镜头必须锁定的姿态或支撑物；
- 单次请求只上传这张状态特定图，不再同时上传站姿图；
- 下一镜只有在故事触发状态变化后，才切换到变化后的角色状态资产。

### Style

风格资产可选。角色、环境和道具已经来自同一审核通过的视觉体系时，不为凑满参考图而重复上传风格图。只有运行时资产之间的材质或渲染风格仍不明确时才占用一个参考槽位。

### Semantic storyboard

每个正文导演镜头都从已审核资产和导演计划生成一张语义导演故事板。它与静态 PPT 的该镜头主图是同一文件，不另造第二套：

- 使用 `kind: storyboard`、`design_source_kind: semantic_storyboard`，并绑定路径、SHA-256 和画面中出现的身份 ID；
- 必须由当前镜头已审核的角色、道具、环境资产和导演计划生成，不能从旧项目、视频截图或逐句图库借图；
- 每镜恰好一张，放在运行时参考列表最后；独立角色、道具和环境资产仍负责身份、材质、尺度和状态；
- 提示词明确它只说明整句内容、人物关系、动作阶段和大致空间方向，不是首帧，不锁定像素、构图、镜位或静态姿势；
- 付费前审核故事板中的人物数量、道具状态、前后站位和知情状态。与入口资产或表演节拍冲突时不得提交；
- 稳定关系镜头可以画决定性状态。连续消耗、拆分或形变镜头应画可读的中间动作与接触关系，不能只画最终状态来要求模型反推全过程。

语义故事板可以包含已经由独立角色资产锁定的同一身份；这不等于上传第二张角色身份图。若输出出现克隆、静态锁帧或过度照抄构图，受控重做时先移除故事板，而不是增加更多参考图。

## 每镜参考图预算

最多 7 张，但“最多”不是“必须用满”。按以下优先级选择：

1. 当前可见角色，每个身份一张
2. 当前唯一环境，一张
3. 当前入口状态的关键道具，每个道具一张
4. 必要时一张群体造型参考
5. 必要时一张风格参考
6. 一张与 `shot_id` 对应的语义导演故事板，并固定放在最后

若超过 7 张，先问哪些角色或道具真正需要在同一个连续镜头内可见；不要用联系表或拼图压缩槽位。必要时按真实叙事边界拆为相邻 R2V 镜头。

## 禁止作为运行时参考

- 同一角色的三视图、表情九宫格或动作联系表
- 未声明为 `semantic_storyboard`、未绑定当前资产或未通过状态审核的成品分镜图
- 同一身份在多张图片中重复出现
- 已排好故事地点、身份关键人物走位或剧情动作但没有按上文声明为当前镜头语义故事板的群像成品图（精确数量匿名群体的中性运行时资产除外）
- 同一道具变化前后两个状态同时出现
- 含无关人物的环境图
- 多个状态拼在一起的道具状态表

这些内容可以作为设计和审核资料保留，但必须标记 `runtime_eligible: false`。

## 资产准备完成条件

- 每个反复出场身份有审核通过的设计母版和至少一张运行时单人物图。
- 每个群像镜头明确区分身份关键成员、重复群体与一次性匿名背景人群。
- 每个连续场景组有审核通过的空环境图。
- 每个有限道具的必要状态有独立资产、状态 ID 和哈希。
- 资产之间风格、尺度和时代一致。
- 角色资产没有无叙事依据、会被模型持续继承的抢眼配饰、束缚物或异常标记。
- 运行时选择不会让同一身份或道具在一次请求中出现两次。

## 同视角简单场景

生成前用 `story_pipeline.py asset-plan` 记录每资产消费者。明确简单、仅一机位且母图camera_contract与机位逐项相同，可声明single_view_reuse_master，让机位资产保留视线合同但引用母图同一文件/哈希。正式assets封存会校验；多机位、反打、不同视线/裁剪或未知复杂度回退原有母图+机位图。不得以文件名相似作为复用依据。
