# R2V 资产合同

## 两层角色资产

三视图在角色设计阶段有价值，但运行时直接上传三视图可能让视频模型把同一身份理解成多个角色。把角色资产分成两层：

1. `design_master`：三视图、表情表或设计稿，用于锁定造型、人工审核和派生运行时资产；标记 `runtime_eligible: false`。
2. `runtime_reference`：一张只显示一个角色的干净参考图；优先全身或四分之三视角、自然站姿、四肢清楚、背景简单；标记 `runtime_eligible: true`。

资产库可以为同一身份保存多个运行时角度，但单个视频请求只能选择其中一个。不要在同一请求中同时发送同一角色的正面、侧面和背面图。

## 资产类型

### Character

必需字段：

- `asset_id`
- `kind: character`
- `identity_id`
- `path` 与 `sha256`
- `runtime_eligible`
- `contains_characters`，只能包含该 `identity_id`
- `appearance_summary`
- `scale_class`

同一镜头引用资产的 `identity_id` 必须唯一。角色与其他角色的相对尺度由镜头计划约束，不通过上传多人合照表达。

### Environment

环境资产必须是空场景：

- `kind: environment`
- `contains_characters: []`
- 无临时人物、动物或人物影子
- 锁定地点、时段、天气、光线方向、主要色彩与可识别锚点
- 同一连续场景组复用同一 `environment_asset_id`

环境资产描述空间本身，不描述本镜头的角色站位。角色站位属于导演提示词。

### Prop

有限道具和会变化的道具必须有 `prop_id` 与 `state_id`：

- 七色花完整状态：`flower_f0_all_seven`
- 撕下黄色后：`flower_f1_without_yellow`
- 完整花瓶：`vase_intact`
- 破碎花瓶：`vase_broken`

命名只是示例；通用代码不得写死具体故事。每次请求对同一个 `prop_id` 只能选择一个入口状态资产。

### Style

风格资产可选。角色、环境和道具已经来自同一审核通过的视觉体系时，不为凑满参考图而重复上传风格图。只有运行时资产之间的材质或渲染风格仍不明确时才占用一个参考槽位。

## 每镜参考图预算

最多 7 张，但“最多”不是“必须用满”。按以下优先级选择：

1. 当前可见角色，每个身份一张
2. 当前唯一环境，一张
3. 当前入口状态的关键道具，每个道具一张
4. 必要时一张风格参考

若超过 7 张，先问哪些角色或道具真正需要在同一个连续镜头内可见；不要用联系表或拼图压缩槽位。必要时按真实叙事边界拆为相邻 R2V 镜头。

## 禁止作为运行时参考

- 同一角色的三视图、表情九宫格或动作联系表
- 已经摆好本镜头人物站位的成品分镜图
- 同一身份在多张图片中重复出现
- 同一道具变化前后两个状态同时出现
- 含无关人物的环境图
- 多个状态拼在一起的道具状态表

这些内容可以作为设计和审核资料保留，但必须标记 `runtime_eligible: false`。

## 资产准备完成条件

- 每个反复出场身份有审核通过的设计母版和至少一张运行时单人物图。
- 每个连续场景组有审核通过的空环境图。
- 每个有限道具的必要状态有独立资产、状态 ID 和哈希。
- 资产之间风格、尺度和时代一致。
- 运行时选择不会让同一身份或道具在一次请求中出现两次。
